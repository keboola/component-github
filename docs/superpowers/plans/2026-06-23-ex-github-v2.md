# keboola.ex-github-v2 — Implementation Plan

> Spec: `docs/superpowers/specs/2026-06-23-ex-github-v2-design.md`
> Branch: `initial-implementation` (stay on it; one PR → main at Phase 8)
> Executed via `superpowers:subagent-driven-development` — one fresh subagent per task, reviewed between tasks.
> Owners: implementation tasks → `component-develop` (delegates schema/UI to `component-build-ui`); test tasks → `component-test` / `generate-vcr-tests`.

## How to use this plan

Each task is independently verifiable: it states the change, the files, and a concrete **Verify**
step (a command to run or an artifact to inspect) that must pass before the next task. Tasks are
ordered so the **PAT path is fully working end-to-end first** (Tasks 1–8), then **OAuth** (Task 9),
then **sync actions** (Task 10), **schema/UI** (Task 11), and **tests** (Tasks 12–15). Run
`ruff check` clean after every code task.

Legend: `[code]` = `component-develop`, `[ui]` = `component-build-ui`, `[test]` = `component-test`,
`[ops]` = kbagent/cf-dev.

## Phase A — Foundations (config + client + registry)

### Task 1 — `[code]` Replace the scaffold with config models

- **Do:** rewrite `src/configuration.py` per spec §5.3/§6.4. Define `AuthType(str, Enum)`
  {`pat`,`oauth`}, `LoadType(str, Enum)` {`full_load`,`incremental_load`}. One `Configuration`
  `BaseModel` holding the merged root+row params (the platform delivers them flattened): `auth_type`,
  `github_token = Field(alias="#github_token", default="")`, `incremental: bool = True`, `endpoint`,
  target fields (`organization=""`, `team_slug=""`, `repository=""`, `pull_number: int|None = None`),
  `load_type = LoadType.incremental_load`, `initial_since=""`, filters (`issue_state`, `pull_state`,
  `milestone_state`). `model_config = ConfigDict(populate_by_name=True, extra="ignore")`. Wrap
  `__init__` to raise `UserException` on `ValidationError`. Add a `model_validator` that raises
  `UserException` when `auth_type==pat` and `github_token` is empty. **No `debug` field** (consumed by
  `ComponentBase`).
- **Files:** `src/configuration.py`.
- **Verify:** `python -c "from src.configuration import Configuration; Configuration(endpoint='user', auth_type='pat', **{'#github_token':'x'})"` constructs; an empty-token PAT config raises `UserException`. `ruff check` clean.

### Task 2 — `[code]` Endpoint registry (the data-driven core)

- **Do:** create `src/endpoints.py` per spec §4.1 + §6.3. Define the `Endpoint` frozen dataclass
  (`name`, `path_template`, `target`, `primary_key`, `envelope`, `incremental_param`,
  `incremental_sort`, `default_params`, `filter_params`, `schema`, `drop_predicate`), the `Target`
  and `Envelope` enums, and `ColumnDef` (name, base type, dotted source path). Populate `ENDPOINTS:
  dict[str, Endpoint]` with **all 33 entries** from spec §4.1, each with explicit `primary_key`,
  `envelope`, incremental config, and an explicit output `schema` (native base types per §6.5). Set
  `drop_predicate="pull_request"` on `repository_issues`; `incremental_sort=True` on `repository_pulls`
  / `organization_repositories` / `user_repos`; `incremental_param="since"` on issues/commits/
  issue_comments/pull_review_comments. `default_params` includes `per_page=100` (and `sort=updated`
  /`direction=desc` for sort-based incremental).
- **Files:** `src/endpoints.py`.
- **Verify:** `python -c "from src.endpoints import ENDPOINTS; assert len(ENDPOINTS)==33; assert ENDPOINTS['repository_issues'].drop_predicate=='pull_request'; assert ENDPOINTS['repository_languages'].primary_key==['repository','language']"`. Every entry has a non-empty `schema`. `ruff check` clean.

### Task 3 — `[code]` Credential resolution (PAT + OAuth resolvers)

- **Do:** create `src/credentials.py` with `resolve_token(configuration, oauth_credentials) -> str`
  per spec §3.1. PAT: return `configuration.github_token`. OAuth: parse `oauth_credentials["#data"]`
  as JSON, return `["access_token"]`; raise `UserException` with a clear message if `#data` is
  missing/unparseable or has no `access_token`. The component reads OAuth credentials from
  `self.configuration.config_data["authorization"]["oauth_api"]["credentials"]` (guard for absence).
- **Files:** `src/credentials.py`.
- **Verify:** unit-level: PAT config returns the token string; an OAuth `#data` of
  `'{"access_token":"gho_x","token_type":"bearer"}'` returns `gho_x`; malformed `#data` raises
  `UserException`. `ruff check` clean.

### Task 4 — `[code]` Auth-agnostic HTTP client: requests + pagination

- **Do:** create `src/client.py` with `GitHubClient(token: str, base_url="https://api.github.com")`.
  `__init__` builds a `requests.Session` with headers `Authorization: Bearer <token>`, `Accept:
  application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`. Implement `fetch(endpoint, path,
  params) -> Iterator[dict]` that: sends the request; unwraps the envelope (`OBJECT` → yield one dict;
  `ARRAY` → yield each; `wrapped:<key>` → yield from the named array; object-map → yield mapped rows
  per §4.5); follows `Link` rel=next **verbatim** until absent (explicit stop condition, no
  hand-built page URLs). `per_page=100`.
- **Files:** `src/client.py`.
- **Verify:** with a mocked/`responses` two-page `Link` sequence, `fetch` returns all rows from both
  pages and stops when `rel="next"` is absent; a `wrapped` response yields the inner array, not
  `total_count`. `ruff check` clean.

### Task 5 — `[code]` Rate-limit wait-and-retry (bounded → UserException)

- **Do:** add rate-limit handling to `GitHubClient` per spec §4.3. On 403/429: if `Retry-After`
  present → sleep that many seconds; elif `x-ratelimit-remaining==0` → sleep until
  `x-ratelimit-reset` epoch (+buffer); else (transient 5xx/network) → exponential backoff base 60s.
  Bound every wait by `MAX_RATE_LIMIT_WAIT_SECONDS` (default 3600, injectable for tests) and a max
  retry count; on budget exceeded raise `UserException` with the §4.3 message. Map a persistent 401 →
  `UserException` ("token invalid/insufficient scope"); 404 on a user-supplied target → `UserException`
  ("not found or no access").
- **Files:** `src/client.py`.
- **Verify:** with a mocked 403 + `x-ratelimit-remaining: 0` + near-future reset and a tiny wait
  budget, `fetch` raises `UserException` (not an unhandled exception); a 401 raises `UserException`.
  `ruff check` clean.

## Phase B — Orchestration (PAT path end-to-end first)

### Task 6 — `[code]` `run()` orchestrator + flattening/write

- **Do:** rewrite `src/component.py` per spec §6.1/§6.2. `__init__`: build `Configuration`, resolve
  token (PAT path for now via `resolve_token`), instantiate `self.client = GitHubClient(token)`.
  `run()` (<30 lines): look up `ENDPOINTS[cfg.endpoint]`; build the concrete path from target params
  (raise `UserException` if a required target is missing); compute `since` from state `last_run` /
  `initial_since` when incremental; capture `run_started_at = datetime.now(timezone.utc)`; iterate
  `self.client.fetch(...)`; flatten each record to the endpoint's schema columns (dotted source paths;
  drop rows matching `drop_predicate`; add `owner`/`repo`/`org` context columns); write a
  **headerless** CSV; `create_out_table_definition(name, primary_key=..., incremental=cfg.incremental,
  schema=...)`; `write_manifest`. On success write `state.json {"last_run": run_started_at.isoformat()}`.
  Keep the per-endpoint logic in the registry — `run()` is identical for all endpoints.
- **Files:** `src/component.py` (+ a small `flatten`/write helper, may live in `endpoints.py` or a
  `transform.py`).
- **Verify:** a local datadir run with a stubbed client (or a recorded cassette from Task 13) over
  `repository_issues` produces the expected CSV + manifest (PK `id`, `incremental: true`, `schema`
  with native types, headerless), drops a `pull_request` row, and writes `last_run`. `ruff check` clean.

### Task 7 — `[code]` Incremental `since`/`updated` + state

- **Do:** wire incremental fully per spec §2.3/§6.6/R6. For `incremental_param` endpoints, pass
  `since=<last_run or initial_since>` as a query param. For `incremental_sort` endpoints (pulls etc.),
  request `sort=updated&direction=desc` and **stop paging** once a record's `updated_at < last_run`
  (client-side stop). First run (no state): use `initial_since` if set, else full history. Watermark
  captured before fetch, written only after a successful write.
- **Files:** `src/component.py`, `src/client.py` (stop-paging hook).
- **Verify:** datadir test with seeded `in/state.json` `last_run` asserts `since` reaches the request
  and the new `last_run` is written; a pulls cassette with mixed `updated_at` stops at the watermark.
  `ruff check` clean.

### Task 8 — `[code]` Native-type manifests + breadth wiring

- **Do:** confirm every registry `schema` emits a proper authoritative `schema` manifest with
  meaningful base types (not all-STRING) and headerless CSV (`has_header` default false). Exercise the
  three non-array envelopes end-to-end (`repository` object, `repository_workflows` wrapped,
  `repository_languages` object-map) so all envelope branches are covered by the orchestrator.
- **Files:** `src/endpoints.py` (schemas), `src/component.py`.
- **Verify:** local runs over one endpoint per envelope shape produce manifests whose `schema`
  carries INTEGER/TIMESTAMP/BOOLEAN where appropriate; the object-map run yields one row per
  language with PK `(repository, language)`. `ruff check` clean.

## Sequencing rationale

- **PAT path first (Tasks 1–8):** zero external dependency (R1 doesn't block it), so the extractor is
  end-to-end runnable before OAuth is touched. Registry (Task 2) before client (Task 4) so the client
  can be tested against real descriptors. Client (4–5) before `run()` (6) so orchestration has a real
  fetch.
- **OAuth (Task 9)** is a thin add-on once the auth-agnostic client + resolvers exist — it only adds a
  branch in `__init__`.
- **Sync actions (10) + schema (11)** depend on the client and the registry being stable.
- **Tests (12–15)** come after the code paths exist; cassettes need the maintainer PAT.
- **Smoke (16)** is the only step needing the platform and confirms the things local tests can't
  (Storage import, native types, default bucket).
